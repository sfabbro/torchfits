# Agent guidance (torchfits)

Pixi is the only supported way to run project code: `pixi run …` or
`pixi run python …`, never a bare `python` / `python3`. Run
`pixi run setup-hooks` once per clone so the local hooks are armed.

## Build and verify

The package is a compiled C++/nanobind extension over vendored CFITSIO, so
pure-Python checks do not exercise native changes.

| When | Command |
|---|---|
| After editing C++, CMake, or `extern/vendor.sh` | `pixi run dev` |
| During edits | `pixi run preflight-push` |
| Docs-only change | `pixi run docs-contract`, then `pixi run docs-links` |
| Before push / PR | `pixi run ci-local` |
| Before a tag | `pixi run release-gate` |

- `pixi run dev` rebuilds and reinstalls the extension in editable mode.
  `pixi run test` does it for you; `preflight-push` does not, so running pytest
  after a native edit without `dev` exercises a stale `.so`.
- `pixi run test` includes the `performance`-marked tests that CI excludes.
  Slow numbers on a loaded machine are not regressions; compare on the same
  quiet host.
- `pixi run ci-local-fast` is the short loop; `pixi run ci-local` is the gate.

## Generated and vendored files

Never hand-edit these; regenerate them instead.

- `extern/cfitsio/` — extracted and patched by `extern/vendor.sh`; the version
  and checksums live in `extern/VERSIONS.txt`.
- `src/torchfits/_core.pyi` — generated by `pixi run gen-stub`; the drift gate
  is `pixi run check-stub` (also `tests/test_native_stub.py`).
- `docs/published-examples/` — synced from `examples/` during the docs build.
- `docs/changelog.md` — assembled from commit subjects by
  `pixi run changelog-update`; `--release` stamps a version.

## Docs

`docs/api*.md` documents the façade exported by `src/torchfits/__init__.py`.
The code is the source of truth: when a signature, flag, default, or exit code
changes, the page changes with it. Any environment variable the docs mention
must exist in `src/`.

- Prefer copy-pasteable Python and CLI recipes over prose.
- No internal vocabulary in user-facing pages.
- Quote Mermaid labels that contain special characters, e.g.
  `id["Label (info)"]`.
- `pixi run docs-contract` and `pixi run docs-links` are part of every docs
  change, not just the pre-push gate.

Pre-tag public-API audit:
[`.cursor/skills/release-api-freeze-review/SKILL.md`](.cursor/skills/release-api-freeze-review/SKILL.md).

## Commits and PRs

- Commit subjects must be Conventional Commits (`fix(io): reject empty HDU`).
  `pixi run changelog-check` parses them and fails otherwise.
- One logical change per PR; the title names the bug or the benchmark case.
- Cite evidence: a test that fails before and passes after, a CFITSIO or
  public-API contract, or a measurement from torchfits-harness (same host,
  same `case_id`).
- Smallest correct diff. No new dependencies without a clear need, no SemVer
  bumps, no force-push.
- Out of scope unless a human labels the issue: HTML / `repr_html` cosmetics,
  markdown wording, or "clean up" without a reproduction.

### Maintainer checkout

In the maintainer's clone, `origin` is the fork `sfabbro/torchfits` and
`upstream` is `astroai/torchfits`. Work is committed directly on the fork's
`main` — no feature branches; a branch is only a temporary landing vehicle and
is deleted once merged. Between rounds the fork carries exactly `main` and is
identical to `upstream/main`:

```bash
git fetch upstream && git merge --ff-only upstream/main
git push origin main
gh api repos/astroai/torchfits/compare/main...sfabbro:main --jq '.status'
```

Anyone who cloned `astroai/torchfits` should branch and open a PR instead.

## Automated PR agents

Read [`.cursor/jules-ledger.md`](.cursor/jules-ledger.md) and search recently
merged PRs first — do not repeat a theme that already landed. The weekly prompt
is [`.cursor/jules.md`](.cursor/jules.md). If research finds nothing serious,
open no PR.

## Evaluation

Benchmarks, upstream parity, migration notes, and CANFAR evaluation live in
[torchfits-harness](https://github.com/astroai/torchfits-harness). Do not import
harness code from `src/torchfits`. Astropy and fitsio are not dependencies of
this repo; `to_astropy` stays a lazy optional converter.

## Notes and agent tooling

Durable notes live under `.cursor/harness/` (playbook, plans) rather than long
chat scrollback; trajectories and state there are local-only. Deferred product
work: [`.cursor/post-1.0-backlog.md`](.cursor/post-1.0-backlog.md).

`.cursor/skills/` and `.cursor/hooks/` are canonical and tracked. `.agents/` and
`.codex/` are installed copies that `.gitignore` excludes. After editing the
canonical tree run `pixi run agent-home` so a client never loads a stale skill
or hook under the same name; `pixi run agent-home-check` is the gate, and a
pre-commit hook runs the sync.

## Environment hygiene

- Never `pip install --user` or install into `~/.local` / `$HOME/.local`,
  especially on CANFAR `/arc/home`.
- Headless or batch runs: keep `PYTHONNOUSERSITE=1` and leave `PYTHONPATH`
  unset.
- On CANFAR, read the `canfar-lab-workflow` skill for mounts, quotas,
  resources, headless behavior, and port forwarding.
